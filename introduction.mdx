D0pam1ne is a self-hosted offensive-security workspace that runs the entire engagement in one place: reconnaissance, manual and automated attacks, OSINT, vulnerability intelligence and client-ready reporting. It pairs the open-source **D0pam1ne engine** (a curated recon and OSINT toolchain driven from the CLI) with **D0pam1ne Pro**, the multi-user web application your team works in, and a **local AI** that never leaves your machine.

<Frame caption="The Command Center: every client and project in one view">

Built by offensive-security practitioners for real engagements, D0pam1ne fuses a fast, modular engine with adaptive evasion and AI-assisted triage, so a tester can take a target from first scope to a signed report without stitching twenty tools together by hand.

## The pipeline

Every engagement moves through the same pipeline. Each stage feeds the next, and everything lands in one project.

<Steps>
  <Step title="Scope">
    Define the client and what is in scope. Recon and attacks act only inside it, and anything out of scope is logged, never probed. See [Client and scope](/concepts/scope).
  </Step>
  <Step title="Recon">
    The engine maps the live attack surface: subdomains, DNS, ports, services, live web, URLs, content, parameters and secrets, with [profiles](/recon/overview) for speed or stealth and an adaptive [Evasive Mode](/evasion/overview).
  </Step>
  <Step title="OSINT">
    Map public exposure before you touch the target: ASNs, people and emails, exposed assets, dorks, email-security posture, breach and infostealer data. See [OSINT](/osint/overview).
  </Step>
  <Step title="Project Data">
    Everything recon and OSINT find lands in [Project Data](/data/hosts-and-services): hosts and services, the [attack-surface graph](/data/attack-surface), URLs, technologies, secrets and the [traffic log](/data/traffic).
  </Step>
  <Step title="Attack">
    [Manual](/attacks/manual-attacks) and [Automated](/attacks/automated-attacks) attacks take recon's results as their targets and run the right tools per category, filing findings as they go.
  </Step>
  <Step title="Needs Review">
    Findings flow into [Issues](/data/issues), where AI triage suggests a verdict and you confirm, edit or reject. Only verified issues reach the client.
  </Step>
  <Step title="Report">
    Turn verified findings into a branded [PDF](/reporting/pdf-report), [interactive HTML](/reporting/interactive-report), Markdown or JSON, then [retest](/reporting/retest) and show what was fixed.
  </Step>
</Steps>

## What sets it apart

<CardGroup cols={2}>
  <Card title="Adaptive Evasive Mode" icon="user-ninja" href="/evasion/overview">
    Not a fixed delay. D0pam1ne paces requests against how the target actually responds, backing off on rate-limiting and blocks, and can route supported tools through Tor with exit-IP rotation so no single address draws attention.
  </Card>
  <Card title="Recon that feeds attacks" icon="diagram-project" href="/attacks/automated-attacks">
    Attacks are not a separate scan. Each category reads the recon signal that justifies it and builds its in-scope target lists automatically, so the right tools run against the right hosts.
  </Card>
  <Card title="Private by design" icon="lock" href="/ai/local-ai">
    The AI runs on your machine via Ollama. No cloud model, no account, no telemetry, and D0pam1ne refuses any AI endpoint that is not local.
  </Card>
  <Card title="Client-ready reporting" icon="file-lines" href="/reporting/report-builder">
    One branded house design across PDF and interactive HTML, with a full per-finding anatomy (risk, impact, attacker view, evidence, remediation) and a matching retest report.
  </Card>
</CardGroup>

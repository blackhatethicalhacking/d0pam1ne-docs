## The finding anatomy

Every finding follows the same anatomy, so a client reads each issue the same way:

<AccordionGroup>
  <Accordion title="Common information" icon="circle-info">
    Total risk, probability, criticality, the weakness class (CWE), the affected network or site, the CVSS score and vector, and the affected assets.
  </Accordion>
  <Accordion title="Description" icon="align-left">
    What the issue is, in plain language.
  </Accordion>
  <Accordion title="Risks" icon="triangle-exclamation">
    What an attacker can do, the business impact, and the likelihood of exploitation.
  </Accordion>
  <Accordion title="Technical description" icon="microscope">
    Root cause, how the weakness manifests, an evidence walkthrough, the affected components and assets, and the conditions and prerequisites.
  </Accordion>
  <Accordion title="Steps to reproduce" icon="list-ol">
    A prerequisites line, then numbered steps a reviewer can follow to see the issue.
  </Accordion>
  <Accordion title="Recommendations" icon="screwdriver-wrench">
    Immediate actions, the configuration or code fix, hardening and defence in depth, compensating controls, references, and how to verify the fix.
  </Accordion>
  <Accordion title="Evidence" icon="file-code">
    The captured request and response, in monospace, that proves the finding.
  </Accordion>
</AccordionGroup>

The report also carries a coverage page (the weakness classes checked) and a glossary (severity, probability, criticality, CVSS, CWE, KEV, EPSS, retest, out of scope), so a non-specialist reader can follow it.

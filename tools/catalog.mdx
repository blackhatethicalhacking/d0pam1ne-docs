D0pam1ne does not bolt twenty scanners together at random. Every tool sits at a
specific point in the flow, fed by the stage before it and feeding the stage
after. This page is the full catalog: **77 tools across 23 categories**, grouped
the way the engine runs them, each with what it does, why it earns its place, and
where its source lives.

<Note>
**Core** tools (marked below) make up the default recon pipeline: 16 tools that
run automatically on every scan. Everything else is **optional**, installed
alongside but run when you choose it, by profile, by category, or by hand. The
attack tools are always run deliberately, never by recon.
</Note>

Three of these are Black Hat Ethical Hacking's own, built for gaps the flow
exposed and marked **BHEH** throughout: **SecretOpt1c**, **D0rkerR3con** and
**AdminPBuster**.

Install, version and update every one of these from the in-app [Tools page](/tools/overview).

## Recon flow

Recon widens the picture one stage at a time. Hostnames resolve to IPs, IPs
reveal open ports, ports reveal web servers, web servers reveal URLs, URLs
reveal parameters and secrets. Each category below is one of those stages, and
its tools exist to carry that stage as far as it goes before handing off.

### Subdomains and DNS

Discover the target's hostnames and resolve them, widening the in-scope surface
before anything is probed.

| Tool | What it does | Core |
| --- | --- | :---: |
| [subfinder](https://github.com/projectdiscovery/subfinder) | Discovers subdomains from dozens of passive sources (certificate logs, DNS datasets, search engines) without touching the target. | ✓ |
| [amass](https://github.com/owasp-amass/amass) | Maps the external surface in depth: subdomains, related ASNs and IP ranges from passive intel. | ✓ |
| [assetfinder](https://github.com/tomnomnom/assetfinder) | Finds subdomains and related domains tied to the target from public sources. | ✓ |
| [dnsx](https://github.com/projectdiscovery/dnsx) | Resolves hostnames and pulls DNS records (A, AAAA, CNAME, MX, PTR and more) to confirm what is live. | ✓ |
| [chaos](https://github.com/projectdiscovery/chaos-client) | Pulls known subdomains from ProjectDiscovery's Chaos dataset (API key required). | |
| [alterx](https://github.com/projectdiscovery/alterx) | Generates likely subdomain permutations to resolve, catching hosts passive sources missed. | |
| [puredns](https://github.com/d3mondev/puredns) | Brute-forces and resolves subdomains from a wordlist, filtering DNS wildcard noise. | |
| [massdns](https://github.com/blechschmidt/massdns) | Resolves very large hostname lists to IPs quickly; the engine behind puredns. | |
| [asnmap](https://github.com/projectdiscovery/asnmap) | Turns an org's ASN into the IP ranges it owns, widening the in-scope network footprint. | |

### Ports and services

Find which ports are open on the resolved hosts and identify the services behind
them.

| Tool | What it does | Core |
| --- | --- | :---: |
| [naabu](https://github.com/projectdiscovery/naabu) | Quickly finds which TCP ports are open on in-scope hosts. | ✓ |
| [nmap](https://nmap.org) | Scans open ports in detail to identify service, product, version and often the OS. | ✓ |
| [cdncheck](https://github.com/projectdiscovery/cdncheck) | Flags IPs belonging to CDNs or WAF edges so testing focuses on the real origin. | ✓ |
| [masscan](https://github.com/robertdavidgraham/masscan) | Sweeps large IP ranges at high speed to find open ports across a wide network. | |
| [rustscan](https://github.com/RustScan/RustScan) | Finds open ports quickly, then hands them to nmap for detailed identification. | |
| [smap](https://github.com/s0md3v/smap) | Reads open-port data passively from Shodan's InternetDB: no packets to the target, no key. | |

### Live web, TLS and fingerprinting

Confirm which hosts serve web, capture their fingerprints, and run the safe
recon-stage checks.

| Tool | What it does | Core |
| --- | --- | :---: |
| [httpx](https://github.com/projectdiscovery/httpx) | Probes hosts for live web servers; records status, title, tech, TLS and CDN. | ✓ |
| [tlsx](https://github.com/projectdiscovery/tlsx) | Collects TLS and certificate details, including the hostnames listed on each certificate. | ✓ |
| [nuclei](https://github.com/projectdiscovery/nuclei) | Template scanner. In recon it runs only safe fingerprinting templates; in the attack phase it runs full vuln templates, a CISA KEV known-exploited pass and DAST parameter fuzzing. | ✓ |
| [gowitness](https://github.com/sensepost/gowitness) | Screenshots every live web page so the team can eyeball the surface at a glance. | |
| [wafw00f](https://github.com/EnableSecurity/wafw00f) | Detects whether a WAF sits in front of a site, and which one. | |

| [urlfinder](https://github.com/projectdiscovery/urlfinder) | Gathers URLs for the target from passive sources. | |

| Tool | What it does | Core |

| [gobuster](https://github.com/OJ/gobuster) | Brute-forces directories and virtual hosts to find hidden content. | |

## OSINT

Gather intelligence from third parties (scan engines, search dorks, code,
email and DNS) without hitting the target directly, so you know the public
exposure before you probe anything. OSINT and automated attacks are
[D0pam1ne Pro](/getting-started/editions) features.

| Tool | What it does | Core |
| --- | --- | :---: |
| [uncover](https://github.com/projectdiscovery/uncover) | Queries internet-wide scan engines (Shodan, Censys, FOFA, ZoomEye, Hunter, Quake) for exposed assets, with your own keys. | ✓ |
| [D0rkerR3con](https://github.com/blackhatethicalhacking/D0rkerR3con-Framework) **BHEH** | Runs search-engine dorks and passive OSINT to surface exposed pages and data. BHEH's own dorking framework. | |
| [theHarvester](https://github.com/laramies/theHarvester) | Gathers emails, names and hosts for the target from public sources. | |
| [github-subdomains](https://github.com/gwen001/github-subdomains) | Finds subdomains mentioned in public GitHub code, using a GitHub token. | |
| [gitleaks](https://github.com/gitleaks/gitleaks) | Scans public repositories for leaked secrets and credentials. | |
| [cloud_enum](https://github.com/initstring/cloud_enum) | Looks for public cloud storage (S3, Azure, GCP) named after the client that may be exposed. | |
| [holehe](https://github.com/megadose/holehe) | Checks an email against many services to reveal where the account is registered. | |
| [dnstwist](https://github.com/elceef/dnstwist) | Generates and resolves lookalike and typosquatting variants of the domain to surface phishing and impersonation risk. | |

## Attack flow

Attack tools are installed by D0pam1ne but run deliberately, never by recon.
Each category reads the recon signal that justifies it and builds its in-scope
target list automatically, so the right tool runs against the right host.
Automated attacks are a [D0pam1ne Pro](/getting-started/editions) feature.
